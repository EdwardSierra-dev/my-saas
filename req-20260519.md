# Operations Screen

## General Requirements

- The Operations Screen must be the main workspace for business/store customers after successful authentication.

- This screen is where business owners interact with all enabled modules and manage their daily operations.

- The interface must follow modern SaaS UI/UX standards with a clean, responsive, and productivity-focused design.

- The layout must behave similarly to a browser workspace using tab-based navigation.

---

# Top Navigation Menu

## Hamburger Menu

- A hamburger menu must appear in the top-right corner of the screen.

### Menu Options

- Change Password
- Edit Profile Information
- Contact Support
- Logout

---

# Dynamic Module Navigation

- The Operations Screen must display dynamic tabs representing the modules enabled for the current business account.

- Tabs must automatically update when:
  - A module is added
  - A module is removed
  - A subscription changes

- Each tab must display:
  - Module name
  - Active module visual indicator

- The currently selected module tab must appear visually highlighted or shaded.

---

# Workspace Layout

- The main workspace must render the selected module inside a central frame/container area.

- The UI must support responsive behavior across:
  - Desktop
  - Tablet
  - Mobile devices

---

# Operations Screen / Chat Module

## General Layout

- The Chat Module must use a split-screen layout.

### Recommended Layout Distribution

- Left panel:
  - Approximately 35%–40%
  - Customer conversation list

- Right panel:
  - Approximately 60%–65%
  - Active chat conversation

- Final proportions may be adjusted according to UX/UI best practices.

---

## Left Panel — Customer Conversations

Each conversation item must display:

- Customer avatar or profile image
- Customer name
- Last interaction preview
- Connection/service status
- Last activity timestamp

---

## Right Panel — Chat Conversation

- The right panel must display the active conversation between:
  - Business/store
  - Customer

---

# Chat Capabilities

The chat system must support sending:

- Text messages
- Voice messages
- Images
- Short videos
  - Maximum duration:
    - 30 seconds

---

# Mobile Permissions

- On mobile devices, the application must request the required permissions for:
  - Camera access
  - Microphone access
  - Media storage access

---

# Voice Message Behavior

- The voice recording interaction must behave similarly to WhatsApp voice messages:
  - Hold to record
  - Swipe to cancel
  - Release to send

---

# Chat Availability Rules

- Customers and businesses may only chat when an active service/order relationship exists.

---

# Service Connection Rules

A service connection may represent:

- A booked service
- A purchased product
- A delivery order
- A customer support interaction

Examples:
- Haircut appointment
- Pharmacy order
- Restaurant delivery
- Product purchase

---

# Chat Retention Rules

- Customer-side chats must remain accessible for:
  - 72 hours maximum after service completion

- After expiration:
  - Chats must disappear from the customer and business UI.
  - Chat records must remain stored securely on the server.

---

# Service Finalization

- Businesses must be able to manually finalize a service/order.

- Once finalized:
  - The chat may become eligible for manual deletion from the UI.

---

# Media Optimization

- Uploaded images and videos must be automatically optimized and compressed to reduce storage consumption and improve performance.

---

# Operations Screen / Delivery Module

## General Requirements

- When switching to the Delivery Module:
  - The Delivery tab must appear visually highlighted.

---

# Delivery Orders List

The module must display a list of active and recent delivery/service orders.

Each order item must contain:

- Customer avatar/profile image
- Customer name
- Address
- Service type
  - Based on business-defined service categories

- Service/order summary
  - Short text description

- Delivery status

### Supported Status Values

- Received
- In Progress
- Delivered
- Returned

- Reception date/time

---

# Delivery Order Sorting

- Orders must be sorted by reception date in descending order.

---

# Delivery Visibility Rules

- Orders may remain visible in the UI for:
  - 48 hours

- After expiration:
  - Orders must disappear from the operational view.
  - Records must remain stored on the server.

---

# Order Identification

- Each delivery/service order must contain:
  - Auto-incremental unique ID

---

# Delivery Details Modal

- The delivery/service summary must behave as a clickable link.

- Clicking the detail link must open a modal containing:
  - Ordered products
  - Service details
  - Quantities
  - Additional notes

---

# Intangible Service Support

- The system must support intangible services in addition to physical deliveries.

Examples:
- Hair styling
- Barber appointments
- Consulting services
- Beauty services

- In these cases:
  - The service description must appear inside the delivery/service detail modal instead of product lists.

---

# Mobile App Considerations

- The mobile application must preserve the same operational flows and capabilities available in the web version.

- The interface must follow responsive and mobile-first design principles.
